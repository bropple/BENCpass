BENCPASS — form shapes

Each of these is a shape that has broken a password manager somewhere. Serve with tools/preview.sh and open over http://127.0.0.1, which counts as a private host so filling is allowed without a certificate.

1. Well-behaved

Sets autocomplete correctly. The easy case.

Expect: anchor on both fields; menu offers matching entries.

2. No autocomplete, meaningless names

ASP.NET-style ids. Only position and the labels give it away.

Expect: username resolves to the field before the password.

3. Search box above the login

The classic misfire — a manager fills the search box.

Expect: the search box is never filled and gets no anchor.

4. Sign-up, two password boxes

Nothing marks which is which. Must not receive an existing password.

Expect: read as a sign-up — the menu offers Generate.

5. Two-step: username now, password next

The Microsoft/Google shape.

Expect: recognised as a username step; the username fills alone. Press Next and the password step replaces it, and should get its own anchor.

6. Framework-controlled input

Refuses a plain el.value = assignment and reverts it, the way a React controlled input does. Only the native setter plus a real input event sticks.

Expect: values survive. If they blank out, the setter path regressed.

7. Form added after load

An SPA rendering its login late. The observer has to notice.

Expect: an anchor appears without reloading.

8. Shipping address

Half marked with autocomplete, half not.

Expect: address fields map; the discount box is left alone.

9. Hidden honeypot

An off-screen password field of the kind used to harvest autofill. Nothing should ever be written here, because nothing fills without a click.

This form has no visible fields.

Expect: no anchor, and the fields stay empty.
